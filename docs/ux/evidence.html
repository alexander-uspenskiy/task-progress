Measured evidence behind the proposals

Every number below was read from the real captures in shots/ (pixel colours, positions) or from hooks/register.tsx. Contrast follows WCAG 2.x: 4.5:1 for text, 3:1 for graphics.

H1 · The progress bar stops telling the truth after about 74 seconds

Blue: the time term of estimate() (expected 60 s, 1.3 margin); the tool-call term (8 calls) reaches the cap sooner, at about 10 calls. Dots: five live readings from the band, 11 to 49 tool calls: all ~95 %. While this session showed a 5-step plan in the app, the band never used it (the mod listens to TodoWrite, TaskCreate, TaskUpdate only; the desktop's own list is update_plan).

H2 · The bar is half empty space, so it reads as a barcode

Live pixel row through the bar (v0.4.2, dark theme)

Measured run lengths: #C6613F ×6 | #252525 ×6 | #C6613F ×5 | #252525 ×6 … in six consecutive frames. {' '} between cells (register.tsx:1431) paints nothing, so only 50 % of the width is ever coloured and the bar reads as vertical stripes, not as a filled gauge.

Same width, no gaps (proposal)

Adjacent background cells, a gradient across the lit cells, a glow cell at the leading edge, a visible track. Same 20 or 28 cells, no new engine feature.

H4 · Pane text is wrapped for 34 cells although the pane has room for about 60 characters

Real capture, dark

"est. $0.30" is pushed onto its own line although the line above it ends about 200 px before the pane's right edge (roughly 35 to 40 % of the row is empty).

Cause

The desktop pane draws in the interface font (proportional, ~8.8 px per character at this zoom), not a monospace grid. pack() counts cells against paneWidth() (34 by default, register.tsx:476), so it breaks lines early; and the tool tally (mcp__windows-mcp__Screenshot×9 ToolSearch×5 …) wraps mid-list because every mcp__server__tool name is spelled in full.

Proposal: lay rows out with Box columns (width, flexGrow, justifyContent) so the engine measures, keep pack() for the CLI only, and shorten MCP tool names to Tool plus a dim server tag.

H5 · Colour emoji break the palette

The Main agent icon renders as a pink colour emoji (see the real captures in both themes) beside a coral rail and blue model name; three unrelated hues in one header. Emoji are already listed under limitations (width varies by font). Proposal: single-width monochrome glyphs tinted by status colour (◆ main, ◈ explore, ▣ test, ◉ review), which also removes the width risk.
